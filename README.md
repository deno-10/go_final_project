# Планировщик задач

Дипломный проект по Go. В браузере можно создать задачу с дедлайном и комментарием, найти её, отредактировать, отметить выполненной или удалить. При выполнении разовая задача удаляется, а повторяющаяся получает следующую дату. Данные хранятся в SQLite и сохраняются между запусками.

## Локальный запуск

Требуется Go 1.24 или новее. Распакуйте архив, перейдите в каталог с `go.mod` и запустите сервер. При первой сборке Go скачает зависимости.

```sh
cd go_final_project
go run .
```

Откройте [планировщик](http://localhost:7540/). При первом запуске в рабочем каталоге появится `scheduler.db`. Для остановки нажмите Ctrl+C.

| Переменная окружения | По умолчанию | Назначение |
| --- | --- | --- |
| `TODO_PORT` | `7540` | Порт HTTP-сервера |
| `TODO_DBFILE` | `scheduler.db` | Путь к файлу SQLite. Родительская папка должна существовать |
| `TODO_PASSWORD` | Пусто | Если задана, при открытии планировщика потребуется войти |
| `TODO_TEST_TOKEN` | Пусто | Cookie для учебных тестов при включённом пароле |

Например, чтобы сменить порт только на один запуск в macOS или Linux, выполните `TODO_PORT=8080 go run .` и откройте [localhost:8080](http://localhost:8080/). В PowerShell перед `go run .` задайте `$env:TODO_PORT = "8080"`.

## Задания со звёздочкой

- Порт и путь к базе можно задать через переменные окружения.
- Планировщик поддерживает все правила повторения из задания, в том числе несколько дней недели, выбранные месяцы, последний и предпоследний день месяца.
- Поиск выбирает задачи по подстроке в заголовке или комментарии с учётом регистра либо по дате в формате `ДД.ММ.ГГГГ`. В списке отображаются до 50 задач по возрастанию даты.
- При заданном пароле фронтенд сохраняет JWT в cookie `token`. Токен действует восемь часов. При перезапуске сервера ключ подписи меняется и требуется повторный вход.
- Dockerfile собирает образ с сервером и фронтендом. Файл базы можно хранить на хосте.

## Как устроен код

| Путь | За что отвечает |
| --- | --- |
| `main.go`, `pkg/server/` | Чтение настроек, открытие базы, регистрация обработчиков, запуск HTTP-сервера |
| `pkg/api/` | Контракт HTTP, проверка входных данных, правила повторения и вход по паролю |
| `pkg/db/` | Схема SQLite, индекс по дате и запросы к задачам |
| `web/`, `tests/` | Исходный фронтенд и интеграционные тесты [Практикума](https://github.com/Yandex-Practicum/go_final_project) |

## Проверка

**Учебный тест `TestTasks` очищает таблицу задач.** Для проверки используйте отдельный файл SQLite. Запускайте обе команды из корня проекта. Пример для macOS и Linux с выключенной аутентификацией приведён ниже.

Первый терминал — сервер с тестовой базой и отдельным портом.

```sh
TODO_PORT=7541 TODO_DBFILE="$PWD/scheduler-test.db" TODO_PASSWORD='' go run .
```

Второй терминал — тесты. Абсолютный путь нужен обоим процессам, поскольку Go запускает интеграционные тесты из каталога `tests`.

```sh
TODO_PORT=7541 TODO_DBFILE="$PWD/scheduler-test.db" go test -count=1 ./...
```

В PowerShell выполните следующие строки в обоих терминалах. Затем запустите `go run .` в первом и `go test -count=1 ./...` во втором.

```powershell
$env:TODO_PORT = "7541"
$env:TODO_DBFILE = Join-Path (Get-Location) "scheduler-test.db"
$env:TODO_PASSWORD = ""
```

В `tests/settings.go` включены `FullNextDate = true` и `Search = true`. Значения `Port = 7540` и `DBFile = "../scheduler.db"` используются, когда соответствующие переменные окружения пусты. Команда только для девяти тестов курса — `go test -count=1 ./tests`. Пакеты можно проверить и без запущенного сервера командой `go test ./pkg/...`.

Для проверки с паролем задайте серверу `TODO_PASSWORD` и войдите в браузере. В инструментах разработчика откройте хранилище cookies сайта, скопируйте значение `token` и задайте его во втором терминале через `TODO_TEST_TOKEN`. Переменная `Token` в `tests/settings.go` прочитает его при запуске тестов.

## Docker

Из корня проекта в терминале macOS или Linux выполните команды ниже. Каталог `data` будет доступен внутри контейнера как `/data`, а SQLite запишет базу в `./data/scheduler.db`. Контейнер запускается с идентификаторами вашего пользователя для записи в каталог хоста.

```sh
mkdir -p data
docker build -t go-scheduler .
docker run --rm --name go-scheduler \
  -p 127.0.0.1:7540:7540 \
  --user "$(id -u):$(id -g)" \
  --mount "type=bind,source=$(pwd)/data,target=/data" \
  go-scheduler
```

Откройте [localhost:7540](http://localhost:7540/). Для входа по паролю перед запуском задайте `TODO_PASSWORD` в окружении и добавьте `-e TODO_PASSWORD` перед именем образа. Остановить сервер можно из второго терминала командой `docker stop go-scheduler`. При следующем запуске с тем же каталогом ранее добавленные задачи останутся доступны.
